# AI Red-Team Platform API Workflows

## Complete Execution Workflow

This document describes the complete end-to-end workflow from authentication through report generation.

### Workflow Sequence

```
1. Authentication
2. Target Selection
3. Test Case Selection
4. Execution Batch
5. LLM Evaluations
6. Risk Scoring
7. Analytics
8. Report Generation
9. Report Download (JSON/PDF)
```

---

## 1. Authentication

### Endpoint: `POST /api/v1/auth/login`

**Purpose:** Authenticate user and obtain JWT access token.

**Request:**
```json
{
  "email": "admin@example.com",
  "password": "TestPass123!"
}
```

**Response:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 1800
}
```

**Follow-up:** Fetch user profile
```
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

## 2. Target Selection

### Endpoint: `GET /api/v1/targets`

**Purpose:** List available targets.

**Authentication:** Required (all roles)

**Response (200):**
```json
[
  {
    "id": 1,
    "name": "Groq GPT OSS 120B",
    "provider": "openai",
    "model_id": "openai/gpt-oss-120B",
    "is_active": true,
    "created_at": "2026-01-15T10:00:00Z"
  }
]
```

### Endpoint: `POST /api/v1/targets`

**Purpose:** Create a new target.

**Authentication:** Required (Admin/Analyst)

**Request:**
```json
{
  "name": "New Target",
  "provider": "openai",
  "model_id": "openai/gpt-oss-120b",
  "description": "Target for red team testing"
}
```

**Response (201):**
```json
{
  "id": 2,
  "name": "New Target",
  "provider": "openai",
  "model_id": "openai/gpt-oss-120b",
  "is_active": true,
  "created_at": "2026-01-15T10:00:00Z"
}
```

## 3. Test Case Selection

### Endpoint: `GET /api/v1/test-cases`

**Purpose:** List available attack test cases.

**Authentication:** Required (all roles)

**Response (200):** Array of test case objects with `id`, `name`, `category`, `severity`, etc.

---

## 4. Execution Batch

### Endpoint: `POST /api/v1/executions/`

**Purpose:** Execute an attack batch against a target.

**Authentication:** Required (Admin/Analyst)

**Request:**
```json
{
  "target_id": 1,
  "test_case_ids": [1, 2, 3]
}
```

**Response (201):**
```json
{
  "id": 1,
  "batch_id": "batch-1234567890abcdef",
  "target_id": 1,
  "status": "running",
  "created_by_user_id": 1,
  "executed_at": "2026-01-15T10:00:00Z"
}
```

**Note:** The `batch_id` is generated by the server and is used throughout the workflow.

### Endpoint: `GET /api/v1/executions/{batch_id}`

**Purpose:** Get execution batch results.

**Authentication:** Required (all roles)

**Response (200):**
```json
{
  "id": 1,
  "batch_id": "batch-1234567890abcdef",
  "target_id": 1,
  "status": "completed",
  "model_response": "...",
  "executed_at": "2026-01-15T10:00:00Z"
}
```

## 5. LLM Evaluations

### Endpoint: `POST /api/v1/evaluations/batch/{batch_id}`

**Purpose:** Run LLM-as-a-Judge evaluations on a complete batch.

**Authentication:** Required (Admin/Analyst)

**Response (201):**
```json
{
  "batch_id": "batch-1234567890abcdef",
  "total_evaluations": 3,
  "passed": 2,
  "failed": 1,
  "inconclusive": 0
}
```

### Endpoint: `POST /api/v1/evaluations/{execution_result_id}`

**Purpose:** Run LLM evaluation on a single execution.

**Authentication:** Required (Admin/Analyst)

---

## 6. Risk Scoring

### Endpoint: `GET /api/v1/risk/batch/{batch_id}`

**Purpose:** Calculate batch risk score and classification.

**Authentication:** Required (all roles)

**Response (200):**
```json
{
  "batch_id": "batch-1234567890abcdef",
  "overall_score": 0.75,
  "risk_classification": "high",
  "severity_distribution": {
    "low": 1,
    "medium": 0,
    "high": 2,
    "critical": 0
  }
}
```

The `RiskScoreResponse` model (defined in `app/schemas/risk_scoring.py`) includes:
- `batch_id`, `total_execution_results`, `total_evaluations`, `unevaluated`
- `passed`, `failed`, `inconclusive`, `scored_evaluations`
- `evaluation_coverage`, `conclusive_coverage`
- `overall_score`, `risk_classification`, `severity_distribution`

---

## 7. Analytics

### Endpoint: `GET /api/v1/analytics/dashboard`

**Purpose:** Get complete dashboard analytics.

**Authentication:** Required (all roles)

**Response (200):** `AnalyticsDashboardResponse` object containing:
- `overview`: Total counts, coverage percentages
- `category_breakdown`: List of `CategoryBreakdown` by attack category
- `target_performance`: List of `TargetPerformance` by target
- `risk_trends`: List of `RiskTrendPoint` over time

**Note:** Ownership filtering applies - analysts/viewers see only their own data. The response model has been fixed and now properly constructs the dashboard data from service queries.

---

## 8. Report Generation

### Endpoint: `GET /api/v1/reports/{batch_id}`

**Purpose:** Get a security assessment report for a batch.

**Authentication:** Required (all roles)

**Ownership:** Filtered by `created_by_user_id` for non-admin users.

**Response (200):** `SecurityReportResponse` object with all report details.

### Endpoint: `GET /api/v1/reports/{batch_id}/export/json`

**Purpose:** Export report as JSON.

**Authentication:** Required (all roles)

**Response (200):** JSON file with `Content-Disposition: attachment; filename="security_report_{batch_id}.json"`

### Endpoint: `GET /api/v1/reports/{batch_id}/export/pdf`

**Purpose:** Export report as PDF.

**Authentication:** Required (all roles)

**Response (200):** PDF binary file with `Content-Disposition: attachment; filename="security_report_{batch_id}.pdf"`

## Known Limitations

- Groq API failures are propagated as runtime errors (no graceful fallback)
- LLM rate limits may cause 422 or timeout errors
- PDF generation may fail for very large reports (many findings)
- Ownership filtering prevents access to other users' reports/exports
- Analytics for analysts/viewers show only their own data
